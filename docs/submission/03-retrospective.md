# 회고 — 한계와 다음 단계

## 무엇을 우선하고 무엇을 맞바꿨나 (요약)

이 프로젝트의 일관된 판단 기준은 **"정확성 > 성능", "저리스크 증분 > 큰 재구조화", "새 의존성 최소화"** 였다.
- 재고 정합성을 위해 비관적 락의 처리량 저하를 **감수**했다(정확성 우선).
- AI 검색은 정확도 상한을 **양보**하는 대신 서버 비용·외부 API 의존을 0으로 만들었다.
- 결제 미완료 처리도 "가짜 품절"을 감수하는 대신 오버셀 불가와 저리스크를 지켰다(payment-first는 미룸).

이 트레이드오프들을 45개의 결정 로그로 남긴 것 자체가 산출물이다 — 면접에서 "왜 그렇게 했는가"를 방어하기 위함.

## 한계 (정직하게)

### 인프라·측정
- **Render 무료 티어(0.1 vCPU)**: 절대 성능이 낮고 15분 후 슬립(콜드 스타트 ~30초). 성능 수치는 **절대값이 아니라 개선 전후 상대 비교로만** 신뢰 가능.
- **k6 자기간섭**: 로컬은 부하 생성기와 앱이 같은 CPU를 나눠 써 절대 처리량이 왜곡된다. 신뢰할 수 있는 정량 성능을 남기려면 부하 생성기와 앱 서버를 **물리적으로 분리한 환경**이 필요하다.
- **병목 진단의 해상도**: 유료 APM/프로파일러 없이는 "라우트별 비용"까지가 블랙박스 k6로 확인 가능한 한계. TypeORM 관계 조립 비용의 내부 분해는 못 했다.

### 아키텍처 전제
- **단일 인스턴스 전제**가 곳곳에 박혀 있다: 인메모리 캐시, RxJS Subject 기반 SSE, cron 없는 lazy 재고 회수. **다중 인스턴스로 확장하면** 공유 캐시(Redis)·분산 락·이벤트 브로커로 재설계가 필요하다.
- **유령 재고 회수가 lazy**: 아무도 조회/주문하지 않는 옵션은 TTL이 지나도 다음 접근 시점까지 재고가 늦게 풀린다(정확성엔 무해, 실시간 대시보드엔 지연).

### 기능
- **AI 이미지 검색의 옷 카테고리 구분 한계**: 자동 시각 유사도만으로는 상의/하의를 안정적으로 가르지 못한다(모델·데이터 한계). 사용자가 카테고리를 직접 고르는 필터로 우회했고, 유사도 임계값은 통계가 아니라 **실측 기반 경험값**이다.
- **Ledger·멀티 PG 미구현**: 프로젝트가 원래 지향한 Double-entry Ledger, 멀티 PG Orchestration, 정산 배치는 아직 설계 단계다. 현재의 결제는 단일 PG(TossPayments) 승인/취소까지.

## 다음 단계

우선순위 순:

1. **Double-entry Ledger + 정산(reconciliation) 배치** — 결제수단 독립 원장. `PENDING`/`EXPIRED`를 정산 스윕의 훅으로 이미 남겨뒀다. confirm 콜백 실패(사용자는 Toss에서 결제됐는데 우리 confirm이 실패)를 배치가 잡아 복구/환불.
2. **멀티 PG Orchestration** — PortOne 추가, PG 라우팅·폴백. Ledger가 PG에 독립적이도록 설계해둔 것을 활용.
3. **payment-first 전환 검토** — 주문을 "결제된 사실"로만 남기고 결제 시도는 `payment_intent`로 분리 → 유령 재고 문제가 구조적으로 소멸. Ledger 작업과 함께 진행.
4. **다중 인스턴스 대응** — Redis 분산 락(재고 회수/결제), 공유 캐시, SSE/이벤트 브로커화.
5. **성능 재측정(신뢰성 있는 수치)** — 부하 생성기 분리 환경에서 p95/처리량/에러율을 정식 측정하고 SLO로 고정. 이미지 검색은 pgvector 인덱싱으로 카탈로그 확장 대비.
6. **관측성** — JSON 구조화 로깅 + APM 도입 후 병목을 라우트 내부까지 분해.

## 5일간 배운 것

- **CI e2e의 값어치**: 유닛 테스트(모킹)로는 못 잡는 엔티티 메타데이터·부팅 오류를 실부팅 e2e가 잡았다(배포 크래시 루프를 CI로 재현·차단). "테스트가 실제 사고를 잡은" 경험.
- **추측 대신 실측**: 성능 병목을 "커넥션 풀이겠지"로 단정하지 않고 A/B·EXPLAIN·비교 라우트로 반증해가며 원인을 좁힌 과정이, 결과 수치(+60%)보다 설명력이 크다.
- **정직한 한계 기록이 강점**: 이미지 검색의 카테고리 구분 한계, 무료 티어 측정 왜곡, lazy 회수의 상호작용까지 숨기지 않고 남긴 것이 포트폴리오의 신뢰도를 높인다.
