사용자가 설명한 내용($ARGUMENTS)을 바탕으로 GitHub 이슈를 만드세요.

## 순서

1. 사용자가 준 설명이 짧으면, 관련 코드(파일 경로, 함수명 등)를 실제로 찾아 읽어서 맥락을 보강한다. 추측하지 말고 코드에서 확인한다.
2. `gh issue list`로 비슷한 이슈가 이미 있는지 확인한다. 있으면 새로 만들지 말고 알려준다.
3. 버그인지 기능/작업 제안인지 먼저 판단하고, 해당하는 템플릿을 읽어서 그 구조를 그대로 따른다:
   - 버그 → `.github/ISSUE_TEMPLATE/bug_report.md` (배경 / 재현 방법 / 기대 동작 vs 실제 동작 / 관련 코드 / 완료 조건)
   - 기능/작업 → `.github/ISSUE_TEMPLATE/feature_request.md` (배경 / 상세 내용 / 비교한 대안 / 완료 조건 / 재검토 트리거)
   - 제목: 무엇이 문제/작업인지 한 줄로, 70자 이내
   - 재현 방법은 AI가 그대로 따라 해서 재현할 수 있을 정도로 구체적인 순서로 쓴다. 뭉뚱그리지 않는다.
4. 버그/기능/문서 등 라벨이 이 레포에 이미 있으면 (`gh label list`) 적절한 라벨을 붙인다. 없으면 라벨 없이 진행하고 사용자에게 알린다.
5. `gh issue create --title "..." --body "$(cat <<'EOF' ... EOF)" [--label ...]`로 생성한다.
6. 생성된 이슈 URL을 사용자에게 알려준다.

## 주의사항

- 이슈 생성은 공개적으로 보이는 행동이므로, 생성 전에 제목/본문 초안을 사용자에게 보여주고 확인받는다.
- 이슈 본문에 실제로 확인하지 않은 추측성 원인/해결책을 단정적으로 적지 않는다 — 확인된 사실과 추정을 구분해서 쓴다.
