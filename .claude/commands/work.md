사용자가 설명한 작업($ARGUMENTS)으로 새로운 작업을 시작하세요.

## 순서

1. `git status`로 현재 브랜치에 처리 안 된 변경사항이 있는지 확인한다. 있으면 사용자에게 먼저 알리고, `/commit`으로 정리할지 그대로 두고 진행할지 물어본다.
2. `git checkout main && git pull`로 base 브랜치를 최신화한다 (충돌 등 문제가 있으면 진행을 멈추고 사용자에게 알린다).
3. `gh issue list`로 이 작업과 겹치는 이슈가 이미 있는지 확인한다.
   - 있으면 그 이슈 번호를 그대로 쓴다 (새로 만들지 않는다).
   - 없으면 `.claude/commands/issue.md`(`/issue`)와 동일한 기준으로 이슈 제목/본문을 작성해서 사용자에게 보여주고, 확인받은 뒤 `gh issue create`로 생성한다.
4. 이슈 번호를 확보했으면, 브랜치 이름을 `{이슈번호}-{영문-슬러그}` 형식으로 만든다.
   - 슬러그는 작업 내용을 짧은 영문 kebab-case로 (예: 이슈 #12 "장바구니 Redis 연동" → `12-cart-redis`)
   - `git checkout -b {브랜치명}`으로 새 브랜치를 만들고 전환한다.
5. "이슈 #{번호} 확인/생성 완료, `{브랜치명}` 브랜치로 전환했습니다"라고 요약해서 알려준다.

## 하지 않는 것

- 이슈 생성이나 브랜치 전환 전에 사용자 확인 없이 진행하지 않는다 (특히 이슈 신규 생성은 공개적으로 보이는 행동이므로 반드시 먼저 보여주고 확인받는다).
- `main`에서 직접 작업하지 않는다 — 항상 새 브랜치를 만든다.
